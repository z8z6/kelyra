# 模块实现归属与编译期导入

> 状态：`@meta module`、运行期使用限制、隐式注解模块的普通加载以及
> 单次编译中的运行期模块筛选已实现。跨目标文件的归属清单与链接前检查
> 仍待实现。

## 已确认的语义

同一个最终程序中，每个普通 Kelyra 模块只有一个运行期实现归属。`import`
让编译器读取声明、类型、泛型定义和注解定义；导入动作本身不复制运行期实现。
模块的静态字段、非泛型函数及编译器生成的类方法也遵守同一归属规则。

参考设计：Rust 以 crate 为编译和链接单元，并把泛型实例作为单独的代码生成
项目；Go 按 package 编译，通过编译产物提供导入信息；Zig 在一次编译中对
`@import` 的文件去重。Kelyra 保留现有的点分模块名，但采用明确的实现归属，
不依赖链接器合并普通函数的重复定义。

- Rust: <https://doc.rust-lang.org/reference/glossary.html#crate>、
  <https://doc.rust-lang.org/stable/nightly-rustc/rustc_monomorphize/collector/index.html>
- Go: <https://go.dev/cmd/compile/>、<https://go.dev/doc/code>
- Zig: <https://ziglang.org/documentation/master/#import>、
  <https://ziglang.org/documentation/master/#Compilation-Model>

## 当前问题

`ModuleLoader` 在一次编译中按模块名去重，但独立的编译器调用不知道其他目标
文件已经实现了哪些模块。`IRGen` 会为非 external 模块生成函数、静态字段和
自动方法。两个目标文件若各自把同一导入模块编入对象，链接时产生重复符号。
目前 `--external-path` 依赖路径约定表达归属，没有可检查的模块清单。

编译器还嵌入了 `std.annotation` 和 `std.meta` 的源码副本。若改成直接加载
`std.annotation` 的普通导入图，`std.meta`、`std.util.string` 等依赖会作为运行期
模块编入每一个目标文件，放大上述问题。编译期读取这些定义不代表程序需要
它们的运行期实现。

## 方案

### 1. 统一模块图，定义 `@meta` 模块

模块加载器只维护一张模块图；显式与编译器提供的隐式导入使用同一解析器、
AST 和语义检查。`@meta` 可标注 `module`、`class`、`function` 和
`method`，表示目标只在编译期存在，不拥有运行期函数或静态存储：

```kelyra
@meta
module std.annotation;
```

`std.meta` 也在源码中声明 `@meta`。`c` 保持普通模块，因为
`import c "header.h"` 会在 `c` 命名空间引入运行期 C 函数；其别名声明
本身不产生实现。
`std.annotation` 声明 `@target(Target.Module, Target.Class, Target.Function, Target.Method)` 的注解，编译器
提供编译期限定效果。`@meta` 与读取元数据的 `meta(...)`
表达式各有用途；模块注解可在全图注解签名注册后检查，不要求模块加载器
仅凭名称或未验证的 AST 文本决定效果。
任何模块都可按普通 `import` 语法导入 `@meta` 模块，以读取类型、注解和
编译期元数据；不能从运行期表达式调用其中的函数或取得其实例。由注解
生成的运行期成员归目标类所在模块所有，不归注解定义模块所有。

`@meta` 模块可以导入普通模块以读取其编译期声明。若普通模块仅通过这些
编译期依赖被加载，它不因此取得运行期实现归属；若也存在从程序入口可达
的普通运行期导入，再按普通模块处理。这里判断的是模块用途和运行期引用，
不能靠 `std.*` 名称特判。普通 `import` 的语法保持一致。

`std.meta` 查询始终读取本次模块图中的定义。Sema 的直接 AST 测试应由测试
工具提供标准库模块图，不再靠 Sema 内嵌另一份定义或跳过缺失导入检查。

### 2. 明确目标文件的所有权

一次编译为每个模块赋予 `Owned` 或 `Imported` 状态。`Owned` 模块生成一份
运行期实现；`Imported` 模块仅用于解析，并在需要时生成外部符号声明。
普通非泛型函数、类的自动方法、虚表和静态字段均以模块为单位应用该状态。
泛型实例按现有实例化规则单独确定归属；跨构建产物复用的实例必须有确定
的链接规则，不能让普通模块的实现退回到重复定义。

`--emit-exe` 无预编译依赖时拥有入口模块及其运行期导入闭包。`--emit-obj`
也可以输出这个闭包，作为库对象。预编译依赖由构建系统指定为 `Imported`，
并把提供实现的对象文件传给链接器；现有 `--external-path` 可在迁移期保留。

每个 Kelyra 对象产物同时输出机器可读的模块归属清单，至少包含模块名、
规范源码路径、目标三元组和内容指纹。编译器链接多个 Kelyra 对象时检查
清单：同一模块有两个所有者时报错并指出两个对象；缺少所有者时报未解析
模块实现；目标或指纹不一致时报不兼容。Kelp 根据依赖图传递对象及清单，
不再只凭源码目录判断归属。

### 3. 实施顺序

1. 注册模块级注解并按 `@meta` 建立编译期模块集合；给模块图添加导入
   用途和实现归属，先覆盖单次编译及现有
   `--external-path` 路径。
2. 将隐式标准库模块交给通用加载器；Sema 和泛型展开器读取同一组 AST，
   删除内嵌源码副本与缺失导入豁免。
3. 让 IR 生成按归属处理函数、静态字段、自动方法与反射数据；验证编译期
   导入不会生成运行期符号。
4. 增加对象归属清单和链接检查，随后让 Kelp 传递清单并逐步替换
   `--external-path` 的路径推断。

验收场景：两个目标文件导入同一库时仅库对象含定义；直接编译一个程序仍能
自动包含其源码依赖；隐式注解加载不产生重复符号；静态字段只有一份存储；
跨对象的泛型、虚调用与运行期反射仍可链接；缺失、重复及不兼容所有者在
调用系统链接器前得到明确诊断。

## 待评审的接口决定

`@meta` 可标注模块、类、函数和方法。普通模块可导入 `@meta` 模块，但其中的
值和函数只能在编译期使用。还需评审
`--emit-obj` 仍输出入口模块及其拥有的导入闭包这一产物边界。

对象归属清单建议作为 `--emit-obj` 的伴随文件，并由 Kelp 自动传递。直接
调用编译器链接既有对象时，应提供清单；普通 C 对象仍可作为无清单的
`--link-input`。清单的文件格式和命令行参数名在实现前确定。

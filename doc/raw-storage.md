# `std.memory.Raw<T>`

`Raw<T>` 提供与 `T` 相同大小和对齐的内联存储，但构造、析构 `Raw<T>`
不会构造、析构其中的 `T`。它是底层内存接口，不是可直接读取的 `T`。
编译器只为标准库中的 `@intrinsic("raw") class Raw<T>` 提供这一语义。

标准库的操作为：

| 函数 | 前提 | 效果 |
| --- | --- | --- |
| `init_copy(slot, source)` | 槽位未初始化 | 在槽位中复制构造 `T` |
| `init_move(slot, source)` | 槽位未初始化 | 在槽位中移动构造 `T`，源仍需析构 |
| `assume_init(slot)` | 槽位已初始化 | 返回指向槽位内 `T` 的借用指针 |
| `drop_init(slot)` | 槽位已初始化 | 析构 `T` |

`Raw<T>` 不记录初始化状态。持有者必须自行记录状态，并在复制、移动和
析构时只操作已初始化的值。持有 `Raw<T>` 字段的类必须显式定义构造、
复制、移动和析构方法；编译器拒绝为这样的类生成默认生命周期操作。

`std.util.maybe.Maybe<T>` 使用布尔字段记录状态。`none()` 不构造 `T`，
`some(value)` 在槽位中复制构造 `T` 后标记为有值，析构时仅在有值的
情况下调用 `drop_init`。因此遍历器的 `next()` 不再因构造 `Maybe<T>`
而分配内存。
